# P5 — Agent tier

**Days 8–10. The LLM finally appears.**

## Goal
Resolve the residue that resists arithmetic — and only the residue. If T2 is working, this tier sees under 10% of records.

## Build
`src/milaan/agent/`
- `graph.py` — LangGraph: `classify → hypothesise → gather_evidence → verify_arithmetic → propose | flag`, iteration cap from config
- `tools.py` — `query_ledger`, `query_settlement`, `compute_expected_net`, `fetch_fee_schedule`, `search_precedents`, `propose_resolution`, `flag_exception`
- `verify.py` — **deterministic Python arithmetic check, not the model.** The agent proposes "credit = payments X+Y minus refund Z"; Python checks whether it sums. Rejected hypotheses loop back. LLMs generate hypotheses well and do arithmetic badly; encode that in the architecture.
- `precedents.py` — RAG over resolved cases, `{cluster fingerprint → resolution class + rationale}`, k from config

## State
```python
class ReconState(TypedDict):
    cluster: Cluster
    hypotheses: list[Hypothesis]
    evidence: list[ToolCall]      # every call + result, for the audit log
    resolution: Resolution | None
    confidence: float
    iterations: int
```

## Exit gate
1. Residual clusters resolved with traceable rationales
2. **Ablation: T1+T2 vs T1+T2+T3.** Quantify the marginal contribution in points of auto-resolve and rupees of cost. If it isn't positive, say so — that's a finding, not a failure.
3. Resolution rate on the first 200 clusters vs the last 200, showing whether precedent retrieval actually helps
4. False-match rate still controlled

## Do not
Build a chatbot. The agent gets one cluster, has seven tools, and terminates.

## If behind
Drop RAG, keep the verify node. Without verify the agent produces confident arithmetic nonsense and false-match rate blows up.
