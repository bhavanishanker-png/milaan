# P6 — Policy gate, audit, journal

**Day 11. Cheap and disproportionately valuable.**

This is what separates a matching script from something a fintech would actually run.

## Build
- `src/milaan/policy/gate.py` — `confidence ∧ amount ∧ class`, thresholds from `config/policy.yaml`, never hardcoded
- `src/milaan/policy/audit.py` — append-only log. Every tier, not just T3: timestamp, actor (`tier1`/`tier2`/`agent`/`human`), inputs, decision, confidence, rationale, resulting journal entry. Hash-chain if time allows.
- `src/milaan/journal.py` — proposed accounting entries for auto-applied resolutions
- `eval/sweep.py` — threshold sweep, plot auto-resolve against false-match rate

## Exit gate
1. Threshold curve plotted, operating point chosen **and justified in one written sentence**
2. Audit log reconstructs the full decision path for any given bank row
3. Chargebacks never auto-apply at any confidence — add `tests/test_gate.py` proving it

## Why the curve matters
It shows the panel you understand this is a business tradeoff dial, not a magic constant. "At our operating point we accept X% escalation to hold false matches under Y%" is a sentence that lands.

## If behind
Skip the hash chain and journal entries. Never skip the gate.
