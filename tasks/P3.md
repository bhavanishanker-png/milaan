# P3 — Baseline match and metrics harness

**Days 3 (pm) – 4. THE CRITICAL GATE.**

Everything after this is measured against the baseline you set here. Without it you are building blind, and the ablation table — your strongest single piece of evidence — cannot be reconstructed retroactively.

## Build
- `src/milaan/match/deterministic.py` — T1: exact UTR + exact batch-total amount. Deliberately dumb. No cleverness.
- `eval/evaluate.py` — the **only** file permitted to read `labels.json`
- `eval/metrics.py` — auto-resolve rate, precision, recall, F1, **false-match rate as its own line**, exception list grouped by reason code
- `src/milaan/report.py` — exception report rendering
- `make evaluate` prints a clean table

## Metrics that must appear
| Metric | Why |
|---|---|
| Auto-resolve % | throughput half of the bar |
| **False-match %** | the number that costs money — report it separately and prominently |
| Precision / recall / F1 | accuracy half of the bar |
| Exceptions by reason code | the honest exception list |
| Cost per 100 records | proves the AI tier earns its place |

## Exit gate
- Baseline on batch A. Expect **70–80%** from T1 alone. If it's 95%+, your generator is too clean — go back to P1.
- False-match rate computed and displayed separately from precision
- `test_no_label_leak` green

## If behind
Cut anything else in the project before this. T1 + T2 with rigorous metrics scores better on this track's stated bar than a full agent with hand-waved results.
